# AX Project Universal Toolkit

> **목적:** 현업 또는 개인으로 새로운 데이터·업무·개발 프로젝트를 수행할 때, 요구사항 파악 → 문제 정의 → EDA → 설계 → 구현 → 실행 → 독립 검증 → 문서화의 품질을 높이는 **작업 절차 및 프롬프트 모음**.
>
> 이 저장소에는 실제 과제 지문, 특정 시험 복기, 조직 내부 자료, 개인정보, 정답 코드, 접근 정보가 **들어 있지 않습니다**. 범용 문서·빈 템플릿·일반 CSV 점검 스크립트만 제공합니다.
>

## 파일 구조 (13개 파일, 하위 폴더 2개)
```text
ai-hackathon-toolkit/
├── README.md                  이 문서: 사용 순서·역할·FAQ·공개 보안
├── AGENTS.md                  AI 공통 원칙·P0/P1/P2·파일 수정 권한
├── QUICK_START.md             초기 점검, 실제 프로젝트/Toolkit 분리
├── PROMPTS.md                 Prompt 1/2 초기화 + 8단계 복사 프롬프트 + 문서화
├── ALGORITHM_GUIDE.md         EDA/설계/구현 구별, 시스템·알고리즘·사용자 역할
├── VALIDATION_GUIDE.md        독립 QA, 데이터/제약/UI 검증, 이슈 보고
├── COMMAND_CHEATSHEET.md     셸 명령, Git, Python, 서버/포트
├── templates/
│   ├── TASK_PLAN.md           요구 ID, 필수도/우선순위, 결정·진행 근거
│   ├── REVIEW_REPORT.md       Prompt 2 테스트·결함·재검증 기록
│   └── HANDOFF.md             검증된 실행/사용/제출 문서 초안
├── scripts/
│   └── profile_csv.py         선택적, 읽기 전용 CSV 기본 점검 도구
├── .gitignore                 Toolkit 저장소의 임시 파일 등 제외
└── LICENSE                    Toolkit 자체 MIT 라이선스
```

## 과제별 작업 흐름·도구·기대 결과
| 단계 | 담당 | 무엇을 하는가 | 과제 프로젝트 안의 산출물(기본 제안) |
|---|---|---|---|
| 1. README·환경·제출 파악 | Prompt 1 | 필수 요구·성공 기준·기존 코드·실행법·제출 조건 확인 | `폴더/TASK_PLAN.md` 초안 또는 응답 |
| 2. 업무 문제 정의 | Prompt 1 + 허용된 업무 담당자/AI | Hard/Soft/Objective/가정, 미확정 규칙 질문 | `폴더/TASK_PLAN.md` 결정·질문 섹션 |
| 3. EDA·품질 확인 | Prompt 1; Prompt 2 일부 재확인 | 실제 입력을 읽어 구조/결측/중복/키/범위 확인 | `폴더/EDA_REPORT.md`; 선택 시 `폴더/data_profile.json` |
| 4. 시스템 설계·알고리즘 선택 | Prompt 1 | 데이터 흐름, 입력/출력 계약, 기준선, 알고리즘 선택 이유 | `폴더/TASK_PLAN.md` 설계·trade-off 섹션 |
| 5. 핵심 기능 구현·계산 | Prompt 1 | 최소 입력→계산→결과(P0)를 실제 실행 | 요구된 소스·결과 데이터·기본 기능 |
| 6. 실행·브라우저 확인 | Prompt 1 + 사용자 | 실제 실행 명령·포트·API·UI/다운로드 확인 | 실행 로그·실제 화면/응답·수정 코드 |
| 7. 독립 QA·재검증 | Prompt 2 → Prompt 1 → Prompt 2 | 원본과 결과의 독립 계산, 결함 수정·재검증 | `폴더/REVIEW_REPORT.md` |
| 8. 최종 문서화·제출 점검 | Prompt 1 (Scribe 모드) | README/코드/Prompt 2 보고를 대조 | **공식 지정** 산출물 |

**문서 저장 안전장치:** `폴더/`가 공식 제출물만 모으는 전용 폴더이거나 자동 수집 대상이라면, 내부 메모(`TASK_PLAN.md`, `EDA_REPORT.md`, `REVIEW_REPORT.md`)를 거기에 넣지 마세요.
대신 공식 규칙이 허용하는 별도 비제출 폴더(예시: `work_notes/`)를 정해 **처음부터 두 세션에 같은 경로를 전달**하세요. 기존 파일 덮어쓰기 금지.

이것은 **기본 진행 순서**입니다. 단계 2의 질문은 3~5단계에서 반복할 수 있고, **독립 QA는 3단계부터 병행**할 수 있습니다.

### 공통 우선순위: P0/P1/P2
- **P0:** 공식 필수 요구사항 및 핵심 동작·주요 제약·필수 실행/제출 조건. 무엇이 P0인지 README 기준으로 결정.
- **P1:** 공식 필수가 아닌 오류처리·안정성·사용성 개선. 공식 필수인 오류처리·문서는 **P0**입니다.
- **P2:** 공식 필수가 아닌 고급 최적화·시각화·외부 연동. 공식 필수인 최적화·시각화는 **P0**입니다.

`Must/Should/Could`는 **요구의 필수 여부**, `P0/P1/P2`는 **실행 우선순위**입니다. 서로 다른 축이며, 공식 필수 사항을 편의대로 낮추지 않습니다.

## Prompt 1 / Prompt 2 — 세션별 소유권

| 역할 | 주요 책임 | 수정 가능한 대상 | 수정하면 안 되는 대상 |
|---|---|---|---|
| **Prompt 1 — Main Developer / Tech Lead** | 분석, 계획, 설계, 기능 구현, 실행, 최종 Scribe 문서화 | 프로젝트 소스 및 `폴더/TASK_PLAN.md`, `폴더/EDA_REPORT.md`, 공식 실행 문서 | 원본 데이터(승인 없는 직접 수정), Prompt 2의 `폴더/REVIEW_REPORT.md` |
| **Prompt 2 — Independent Reviewer / Senior QA** | 원본·공식 요구·최종 결과 독립 검증 및 재검증 | `폴더/REVIEW_REPORT.md`, 별도 승인된 QA 테스트 파일 | 앱 소스, 원본 입력, Bash 1 문서 |

- `pwd`와 공유 테스트로 확인 필수.
- 역할 Prompt를 입력하면 **초기 조사/검증 계획**이 나오지 완성된 앱이 저절로 생성되지는 않습니다. 단계별 작업 지시를 이어서 줘야 합니다.
- 두 세션 분리가 불가능하면 Prompt 1만 사용하되 **별도 검증 절차**를 수행합니다. Prompt 2가 있다고 자동으로 독립성이 확보되는 것도 아닙니다. 검사 방법과 입력 근거를 분리해야 합니다.

##주의사항
- GitHub 웹에서 `.md` 수정 → **Commit changes** 하면 새로운 `git clone`은 수정된 최신 커밋을 가져옵니다.
- 이미 clone했다면, **Toolkit 폴더에 로컬 변경이 없을 때** `git -C ai-hackathon-toolkit pull --ff-only`로 갱신합니다. 로컬 변경이 있으면 충돌 처리가 먼저입니다.
- Toolkit 폴더를 과제 프로젝트와 혼동하거나 Toolkit 전체를 과제 제출물에 그대로 포함하지 않습니다.
- GitHub Public 저장소에는 **진행 중인 과제의 README·입력/결과 데이터·스크린샷·대화 내용·API 키·업무 담당자의 답변을 업로드하지 않습니다**. `폴더/`도 과제 저장소의 산출물이므로 공개 게시 금지 여부를 별도 확인해야 합니다. Toolkit의 `.gitignore`가 다른 저장소를 자동 보호하지는 않습니다. **커밋 직전에 `git status --short`와 `git diff --cached --name-only`로 공개 대상 파일을 직접 확인**합니다. 무심코 업로드한 자료는 나중에 삭제해도 Git 이력이나 복제본에 남을 수 있습니다.

## 보안·정확성 원칙
1. 비공개 문제·실제 데이터·개인정보·직원/고객 정보·토큰·내부 대화·스크린샷을 공개 GitHub나 허가되지 않은 도구로 보내지 않습니다. 공개 저장소와 **과제 작업 공간은 엄격히 분리**합니다.
2. 외부 공개 코드·MCP·플러그인·라이브러리·AI 도구는 **현재 프로젝트 규정이 허용한 경우에만** 사용합니다. 라이선스와 출처를 준수하며 완성된 외부 솔루션으로 과제 전체를 대체하지 않습니다.
3. AI가 "완료"라고 해도 파일·실행 명령·로그·독립 검증이 없는 항목은 검증 완료가 아닙니다.
4. 미검증·가정·불가능·미구현은 명확히 표시합니다. 데이터 수정·예외 레코드 제외·강제 조건 완화는 승인 없이 하지 않습니다.
5. 이 Toolkit은 **공개 가능한 일반적인 작업 방법론**으로 구성했습니다.
